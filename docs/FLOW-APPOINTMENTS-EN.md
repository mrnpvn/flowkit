# Clinic appointments — reminders with confirm/cancel links

English version of the clinic workflow, prepared for the n8n template library.
File: [`workflows/clinica/appointment-reminders-confirm-cancel.json`](../workflows/clinica/appointment-reminders-confirm-cancel.json)

What it does: books appointments from a hosted form, emails every patient booked for tomorrow a reminder with **confirm** and **cancel** links, keeps the status in Google Sheets and alerts the team on Telegram — including the **freed slot** when somebody cancels.

Everything runs in your own n8n. No paid services, no API keys included, no data leaves your instance except the emails you send and the Telegram messages to your own chat.

---

## 1. Before you import

| Requirement | Why |
|---|---|
| n8n 1.40+ (tested on 2.43.8) | Node versions used by the workflow |
| Google account with Sheets | Stores appointments; the workflow reads and writes it |
| Telegram bot + team chat | Team alerts (3 nodes) |
| SMTP account (or Gmail OAuth) | Sends the reminder emails |
| A public URL for n8n | The confirm/cancel links must be reachable from the patient's phone |

The public URL is only strictly needed for part C. If your n8n is on `localhost`, patients will open a dead link — the rest of the workflow still works.

## 2. Create the sheet

New Google Sheet, one tab named **Appointments**, with these headers in row 1, exactly as written:

| ID | Patient | Phone | Email | Treatment | Date | Time | Status | Notes | Created | Updated |
|---|---|---|---|---|---|---|---|---|---|---|

- `ID` is generated by the workflow (`APT-20261112093000-ab12cd34ef`) and is the key used to update the row. Never edit or delete it.
- `Date` accepts `2026-11-12` (ISO, recommended — the form sends this), `12/11/2026` (day/month/year) or a Google Sheets date cell.
- `Status` values used: `Pending`, `Confirmed`, `Cancelled`, `Attended`. Anything starting with `cancel` or `attend` is ignored by reminders.
- Keep one row per appointment and do not delete rows that still have live links: the patient would get an invalid-link page.

## 3. Configure the nodes (five steps)

1. **Appointment booking form** — leave the path as is or change it; the public form URL is shown in the node.
2. **Save appointment**, **Read appointments**, **Update appointment status** — in each of the three Google Sheets nodes, pick the document and the `Appointments` sheet, and connect your Google account.
3. **New appointment alert**, **Tomorrow's agenda**, **Appointment change alert** — pick your team chat in each Telegram node (same chat in all three).
4. **Build patient reminders** — the two lines at the top of the code:
   ```js
   const BASE_URL = 'https://your-n8n.example.com';
   const CLINIC_NAME = 'your clinic';
   ```
   `BASE_URL` must be the public URL of the same n8n instance (no trailing slash needed) and must match the webhook path `flowkit-appointment`.
5. **Reminder email** — set the sender (`fromEmail`) and the SMTP credential. Then save and test.

## 4. Test it before going live

1. Open the form and book an appointment **for tomorrow**, using an email address you can read.
2. Check the row in the sheet: status `Pending`, `ID` filled, `Created`/`Updated` in `yyyy-MM-dd HH:mm`.
3. Run **Build patient reminders** manually (Execute step) and send the email — you should get one message for tomorrow only.
4. Click **confirm** in the email: the sheet must move to `Confirmed`, the team must get an alert, and you must see the green page.
5. Book a second appointment, click **cancel**: status `Cancelled`, alert with `Freed slot: dd/mm/yyyy at hh:mm`.
6. Open the webhook URL with no parameters: you must get the grey page with HTTP **400**.
7. Activate the workflow and let the 18:00 schedule run once.

## 5. How the three parts work

**A) Booking** — form → normalize (11 fields, `Pending`, timestamps) → append row → Telegram alert. The `Set` node uses `includeOtherFields: false`, so the sheet gets exactly the 11 columns above.

**B) Reminders (daily 18:00)** — reads the sheet and runs two independent branches:
- *Build patient reminders* → one email per appointment tomorrow, skipping cancelled/attended rows, rows without email and unparseable dates; the message contains date, time and the two links — **never the treatment**.
- *Build tomorrow's agenda* → one Telegram message with time, patient, treatment label, status and a `NO EMAIL` marker for patients who must be phoned. No appointments tomorrow → no message at all.

**C) Patient links** — `GET /webhook/flowkit-appointment?id=…&action=confirm|cancel&date=…&time=…` → parse → IF valid → update row by `ID` → Telegram alert → HTML page (200 confirm/cancel, 400 invalid). Date and time travel in the link only to describe the freed slot in the alert; the update itself is keyed by `ID`.

Duplicate clicks are safe: the second click just writes the same status again.

## 6. GDPR and health data

An appointment at a clinic is **health-related data (art. 9 GDPR)**, even without a diagnosis. Before using this workflow with real patients:

- include appointment reminders in your privacy policy and collect informed consent where your legal basis requires it;
- keep the sheet restricted to staff who need it, and the Telegram chat private;
- the email deliberately contains **no treatment or clinical reason** — keep it that way;
- do not store diagnoses in `Notes`; use the sheet only for scheduling;
- delete or anonymise rows when they are no longer needed.

This workflow does not diagnose, does not recommend treatments and takes no clinical decisions.

## 7. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| No reminder emails | Appointment is not dated tomorrow, status starts with `cancel`/`attend`, or `Email` is empty. Check the `NO EMAIL` marker in the agenda. |
| `Date` not recognised | Value is a free text date Google converted oddly. Use `yyyy-MM-dd` or `dd/mm/yyyy`. |
| Email fails but the workflow continues | The email node is set to *continue on error* so one bad address does not stop the rest. Check SMTP credentials and the n8n execution log. |
| Patient sees "Invalid link" | `BASE_URL` does not match the webhook path, the `ID` was edited, or the link was truncated by the email client. |
| Links point to localhost | `BASE_URL` was not replaced, or n8n has no public URL / tunnel. |
| Webhook returns 404 | Workflow is not active. Inactive workflows only respond to the test URL. |
| Status never updates | The `ID` in the sheet and in the link differ, or the sheet node points to another tab. |
| Two rows for one appointment | The form was submitted twice — nothing deduplicates by patient. Cancel the duplicate. |
| Team does not get the agenda | No appointments tomorrow (expected), or the Telegram chat is different in that node. |
